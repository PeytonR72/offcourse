# Domain documentation

This is a single-context project. Use root `GLOSSARY.md` for shared terms and `docs/adr/` for architecture decisions.

Before exploring an implementation, read the glossary and any ADRs relevant to that ticket if they exist. Proceed when those files are absent; create them lazily as terminology or decisions are resolved.

Use the glossary's vocabulary in code, tickets, tests, and explanations. Surface conflicts with an existing ADR before changing its decision.

The official product rules and ticket definitions remain in `docs/OFFCOURSE_SPEC.md`.
